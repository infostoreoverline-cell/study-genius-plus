# M05 - Provider e Chiavi

## Stato: Completato

### Cosa è stato costruito
1. **Contratti Provider**: Definiti i tipi in `packages/contracts/src/providers.ts` per standardizzare le chiamate e le risposte AI.
2. **SecretStore (DPAPI)**: Implementata la classe `SecretStore` in `packages/providers/src/secret_store.ts` che cripta e decripta in modo asimmetrico le chiavi API utilizzando la crittografia nativa di Windows DPAPI (`powershell.exe`). 
3. **GoogleAdapter & DeepSeekAdapter**: Implementati per supportare l'ecosistema @google/genai (Gemini) e le chiamate dirette via `fetch` per DeepSeek.
4. **Gateway AI**: Sviluppata la classe `AiGateway` che gestisce l'intero ciclo di vita di una richiesta (risoluzione credenziali, decriptazione, prenotazione budget, esecuzione ed effettivo consumo/storno nel Ledger).
5. **Rotte Settings API**: Creata la rotta per aggiungere nuovi provider (`POST /api/settings/keys`) e per visualizzare lo stato.
6. **Integrazione Dispatcher**: Integrazione del Gateway nel Dispatcher per l'elaborazione dei job `ai_generation`.

### Prove tecniche eseguite
- Unit test per `SecretStore` eseguito via Vitest (passato, crittografia e decrittografia confermate su Windows).
- L'ambiente SQLite memorizza solo blob crittografati in DPAPI (nessun testo in chiaro).

### Cosa funziona davvero
- Inserimento di chiavi e crittografia DPAPI nativa via PowerShell (gestione memory-safe tramite `EncodedCommand`).
- Ciclo di vita delle chiamate ai provider interfacciato correttamente con il Ledger (prenotazione/storno automatici in base agli errori `429` e generici).
- Chiamate protette al Gateway integrato nel Node Dispatcher.

- Nessuna dipendenza per l'interfaccia UI impostata (sarà in M06).
