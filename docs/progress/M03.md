# M03 - Lavori Persistenti

## Cosa funziona davvero
- Il ciclo di vita del job (creazione, start, pause, resume, cancel).
- L'assegnazione e l'avanzamento dei task, con gestione degli errori (inclusi simulazioni di retry falliti o sovraccarichi del provider).
- Il loop asincrono in background (`Dispatcher`) che implementa il lease dei task (`lease_owner`, `lease_until`) su database SQLite (sfruttando `RETURNING` per operazioni di concorrenza).
- Event-Sourcing su tabella `job_events` con dispatch via Server-Sent Events (SSE) esposto da un router ExpressJS.
- L'integrazione di base in memoria con mock `SimulatedProvider` che fornisce progressioni finte.

## Test eseguiti
- Sono stati eseguiti i test di integrazione (`apps/server/tests/jobs.test.ts`), simulando una reale chiamata HTTP al server locale per:
  - Bootstrap dell'auth (creazione sessione).
  - Inizializzazione di un job via POST a `/api/v1/jobs`.
  - Avvio effettivo del job (creazione task e change state a `QUEUED`).
  - L'attesa via connessione SSE fino allo stato terminale (`COMPLETED` o `FAILED`), gestendo correttamente la latenza del worker simulato e gli stream SSE asincroni.
- I test (`node:test`) sono stati configurati e superati tutti con successo (5 passati su 5).
