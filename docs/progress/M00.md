## Verifiche realmente eseguite:
- **Transazione e backup SQLite (`better-sqlite3`)**: Eseguita transazione WAL con inserimento dati e simulazione di un backup locale `test.db` -> `backup.db`. Funziona correttamente su Windows.
- **Generazione PDF (`playwright`)**: Eseguita generazione di un PDF da stringa HTML con SVG incorporato usando Chromium headless. Funziona senza problemi con i binari precompilati scaricati.
- **Secret Helper DPAPI (`win-dpapi`)**: L'installazione di questo pacchetto **ha fallito** durante la fase di npm install su Windows perché richiede i build tool di Visual Studio C++. Si tratta di un blocco di compilazione su sistema target.
- **Gestione SDK Google (`@google/genai`)**: Provata istanziazione fittizia con chiamata `gemini-3.5-flash-lite`. Il costrutto base del payload funziona, nessuna chiamata reale effettuata (nessun addebito).
- **Import Parser PDF (`pdf-parse`)**: Fallito durante l'esecuzione con errore nativo Node ESM `ERR_PACKAGE_PATH_NOT_EXPORTED`. Essendo il workspace strettamente configurato `type: "module"`, molti parser PDF obsoleti generano problemi di risoluzione path esportati.

## Limiti o problemi aperti (Blocchi):
1. **Blocco C++ su `win-dpapi`**: Senza i build tools di MSVC l'installazione fallisce su Windows standard pulito. Possibile alternativa: crittografia nativa Node.js legata alla chiave macchina o usare un eseguibile PowerShell C# minimale.
2. **Blocco ESM per `pdf-parse`**: È necessario utilizzare un bundler per l'adattamento, usare un package alternativo compatibile ESM (come `pdfjs-dist`), o instanziarlo via `createRequire`.
