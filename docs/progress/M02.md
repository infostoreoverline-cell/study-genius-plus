# Progress Report: M02 — App locale e UI base

## Cosa funziona davvero
- **Workspaces:** Il monorepo logico è stato configurato per usare npm workspaces (`apps/*`, `packages/*`). Le dipendenze sono state installate.
- **Backend (Express 5):** Il server HTTP `apps/server` è funzionante. Implementa difese a livello di Origin, Host header e IP address (accetta solo richieste da Loopback). Il `LOCK_FILE` impedisce avvii multipli simultanei.
- **Gestione sessioni e bootstrap:** L'autenticazione è implementata usando un bootstrap token (inviato stdout all'avvio) per rilasciare sessioni (gestite in RAM momentaneamente per test locale e sicurezza loopback).
- **Frontend (React + Vite):** Inizializzato il progetto Vite in `apps/web`. È stata creata una Single Page Application base in React (`App.tsx`) provvista di un layout (Sidebar) e viste mockate per: New Job, Workspace, Archive, Figures e Settings.

## Test eseguiti
- `apps/server/tests/security.test.ts`:
  - `Health check is available`: L'endpoint ready risponde su localhost.
  - `Missing bootstrap token yields 401`: Rifiuta token errati o assenti.
  - `Valid bootstrap token yields ok`: Accetta il token di avvio generato in runtime.
  - I test passano con successo (utilizzato Node `node:test`).
- **Verifica manuale (Lock file)**: Testato controllo esistenza `app.lock`. 
- **Verifica manuale (Frontend)**: Frontend Vite scaffold completato e UI React funzionante come mockup.

## Blocchi o problemi aperti
- M02 non si preoccupa di compilare i frontend come assets statici serviti dall'express server in "produzione", deleghiamo a un comando build per i rilasci futuri. Per ora Vite funge da dev server autonomo sulla porta 5173.
- Il token bootstrap dovrà essere passato dal launcher nativo in M14; per ora, all'avvio backend (`npm start`) verrà stampato a schermo e l'app React, per comunicare, dovrà prevedere un login manuale o auto-iniettarsi il parametro, cosa che implementeremo col layer API effettivo a partire da M03.
